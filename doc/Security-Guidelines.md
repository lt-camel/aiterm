# aiterm 安全规范

**版本：v0.1**

定义 `aiterm` 在处理 SSH 凭据、密钥、连接时的安全红线。对应架构文档 [§20–§21](Architecture.md)。

---

# 1. 私钥处理

- 私钥文件**只读**，读取后不持久化到内存以外
- **禁止**在日志、错误消息、CLI 输出中包含私钥内容
- **禁止**将私钥内容写入临时文件
- 私钥 passphrase 通过交互式输入获取，不接受命令行明文参数
- 私钥文件权限检查：若权限过宽（如其他用户可读），警告

---

# 2. Known Hosts

严格遵循架构文档 [§20](Architecture.md) 三态：

| 状态 | 行为 | 安全要求 |
|------|------|----------|
| Match | 继续连接 | — |
| Unknown | 首次连接，提示用户确认 | 记录用户选择，确认后写入 known_hosts |
| Mismatch | **拒绝连接** | **禁止**用 `StrictHostKeyChecking=no` 绕过 |

- Mismatch 错误**只输出主机密钥指纹**，不输出密钥全文
- 用户拒绝连接未知主机时，退出码 5，不写入 known_hosts
- known_hosts 文件路径：`~/.ssh/known_hosts`，跨平台解析

---

# 3. 认证

第一阶段只支持 `IdentityFile` 认证。

未来扩展（不在第一阶段）：
- SSH Agent
- Password（交互式，不落参数）
- Passphrase
- Hardware Security Key

安全要求：
- 密码/passphrase **不落日志**
- 认证失败错误消息不泄露具体原因细节（避免枚举攻击）

---

# 4. 日志红线

| 禁止输出 | 允许输出 |
|----------|----------|
| 私钥内容 | 私钥文件路径 |
| 密码 / passphrase | 认证方式（publickey） |
| 主机密钥全文 | 主机密钥指纹（SHA256） |
| 用户名 + 主机的明文组合 | Target 名称（用户已知） |

- 日志级别 `debug` 也不得突破红线
- 第三方库（ssh2）的日志须经我们 logger 过滤后再输出

---

# 5. 临时文件

- 临时文件使用系统临时目录，文件名随机
- 使用后立即删除（`finally` 块）
- 下载文件直接写入目标路径，不经临时中转（除非需原子性）
- 临时文件权限设为仅当前用户可读写

---

# 6. 命令执行

- `exec` 命令的 payload **原样传递**给远程 Shell，不做本地解析
- 不对命令内容做安全过滤（那是远程服务器的职责）
- 但 CLI 参数解析须防注入（如 `--` 分隔符正确处理）

---

# 7. 配置文件安全

- SSH Config 文件权限检查：若其他用户可写，警告
- 不执行 SSH Config 中的 `ProxyCommand` 等可执行指令（第一阶段）
- IdentityFile 路径展开 `~` 后校验是否在可信目录

---

# 8. 依赖安全

- 定期 `npm audit` 检查依赖漏洞
- `ssh2` 锁定主版本，升级前审查 changelog
- 不引入未维护或已知漏洞的依赖
